# Production RAG Service

A document-based Retrieval-Augmented Generation (RAG) application that allows users to upload documents, ask questions, retrieve relevant evidence, and receive source citations.

Built with FastAPI, React, ChromaDB, and Sentence Transformers.

## Project Overview

This project implements a code-based RAG pipeline for document question answering.

Users can upload supported documents, process their content into overlapping chunks, generate embeddings, store them in ChromaDB, and ask questions against the uploaded collection.

The system uses similarity-based retrieval and abstains when retrieved evidence does not meet the configured relevance threshold.

## Features

- PDF, DOCX, PPTX, TXT, and Markdown document support
- Document text extraction and chunking
- Sentence Transformer embeddings
- Persistent ChromaDB vector storage
- Semantic similarity retrieval
- Source citations and retrieved chunk inspection
- Similarity-based abstention
- SHA-256 duplicate detection
- Document listing and deletion
- React frontend
- 25-question golden evaluation dataset
- Retrieval metric calculations
- Chunking and similarity threshold experiments
- Request ID and latency logging
- API documentation through Swagger

## Technology Stack

| Component | Technology |
|---|---|
| Backend | Python 3.11, FastAPI |
| Frontend | React, Vite |
| Vector database | ChromaDB |
| Embedding model | all-MiniLM-L6-v2 |
| Document processing | PyPDF, python-docx, python-pptx |
| Evaluation | Python-based evaluation framework |
| Testing | Pytest |

## Architecture

1. User uploads a document through the React interface.
2. FastAPI validates the file and checks its SHA-256 hash.
3. The document loader extracts text and metadata.
4. The chunker creates overlapping text segments.
5. Sentence Transformers generates embeddings.
6. ChromaDB stores vectors and metadata.
7. User submits a question.
8. The system retrieves the top relevant chunks.
9. Similarity threshold filtering determines whether sufficient evidence exists.
10. The application returns an extractive answer, citations, and retrieved evidence, or abstains.

See [DESIGN.md](DESIGN.md) for architecture and design decisions.

# System Design — Production RAG Service

## 1. Overview

The Production RAG Service is a document question-answering application built using a code-based Retrieval-Augmented Generation architecture.

The system processes uploaded documents, converts their text into embeddings, stores those embeddings in a persistent vector database, and retrieves relevant evidence in response to user questions.

The application prioritizes traceability by returning source citations and retrieved chunks. It abstains when retrieved evidence does not meet the configured similarity threshold.

## 2. Technology Choices

| Component | Selected Technology | Reason |
|---|---|---|
| Backend | FastAPI | Typed request validation, API documentation, and Python integration |
| Frontend | React and Vite | Interactive document and question-answering interface |
| Embeddings | all-MiniLM-L6-v2 | Compact sentence embedding model with relatively low inference cost |
| Vector database | ChromaDB | Persistent local vector storage and metadata filtering |
| PDF extraction | PyPDF | Python-based PDF text extraction |
| DOCX extraction | python-docx | Word document text extraction |
| PPTX extraction | python-pptx | Presentation text extraction |
| Testing | Pytest | Automated API and component tests |

## 3. System Architecture

The application contains four major layers:

1. React frontend
2. FastAPI API layer
3. Document ingestion and retrieval pipeline
4. ChromaDB vector storage

## 4. Document Ingestion

The ingestion pipeline performs the following steps:

1. Validate the file extension.
2. Read the uploaded file.
3. Enforce the 15 MB maximum file size.
4. Calculate the SHA-256 hash.
5. Reject duplicate file content.
6. Generate a unique document ID.
7. Extract text and source metadata.
8. Split text into overlapping chunks.
9. Generate embeddings.
10. Store vectors and metadata in ChromaDB.
11. Save the document record in the JSON registry.

Supported formats:

- PDF
- DOCX
- PPTX
- TXT
- Markdown

The system preserves document identifiers, filenames, page or slide information, and chunk positions as metadata.

## 5. Chunking Strategy

The default configuration is:

- Chunk size: 800 characters
- Chunk overlap: 150 characters

Overlap preserves context across chunk boundaries. Larger chunks can retain more surrounding information, while smaller chunks can provide more precise retrieval units.

Two configurations were experimentally compared:

| Metric | Configuration A | Configuration B |
|---|---:|---:|
| Chunk size | 800 | 500 |
| Overlap | 150 | 100 |
| Total chunks | 863 | 1,313 |
| Hit Rate@5 | 100% | 100% |
| Recall@5 | 100% | 90% |
| MRR | 0.6667 | 0.7067 |
| Average retrieval latency | 0.0208 sec | 0.1265 sec |

Configuration A was selected as the provisional default because it achieved full recall on the verified subset and lower measured retrieval latency.

Configuration B achieved a higher MRR, indicating better average ranking position, but lower recall in this experiment.

These results are based on a limited manually verified subset and a single latency measurement run. They should not be treated as universal performance guarantees.

## 6. Embedding Model Selection

Selected model:

`sentence-transformers/all-MiniLM-L6-v2`

Reasons:

- Compact model size
- 384-dimensional embeddings
- Suitable for semantic similarity search
- Lower computational requirements than many larger embedding models

Alternatives include larger Sentence Transformer models and hosted embedding APIs.

Larger models may improve semantic representation but generally increase compute requirements, memory use, and inference cost.

Hosted embedding APIs can reduce local infrastructure requirements but introduce network dependency, external service cost, and data privacy considerations.

The selected model provides a practical local baseline for this portfolio project.

## 7. Vector Database Selection

Selected vector database: ChromaDB.

Reasons:

- Persistent local storage
- Simple Python integration
- Metadata support
- Similarity search
- Suitable for local development and portfolio demonstration

Alternatives:

- FAISS: efficient vector similarity search, but persistence and metadata management require additional application code.
- Pinecone: managed vector database with hosted infrastructure, but introduces external service dependency and operational cost.

ChromaDB was selected to keep the project reproducible and locally executable without requiring a hosted vector database account.

## 8. Retrieval Strategy

The retrieval pipeline:

1. Converts the question into an embedding.
2. Searches ChromaDB for the top K similar chunks.
3. Uses a default top K value of 5.
4. Converts vector distance into a similarity score.
5. Filters results using a configured threshold of 0.30.
6. Abstains if no retrieved chunk meets the threshold.

The threshold is a configurable experimental value, not a universally calibrated relevance score.

A lower threshold can increase recall but may admit irrelevant evidence. A higher threshold can reduce unsupported answers but may reject valid questions.

The threshold experiments are documented in EVAL.md.

## 9. Answer Generation and Grounding

The current implementation uses extractive answer generation.

It constructs responses from retrieved document text and creates citations from retrieved chunk metadata.

This design avoids introducing a generative model that could produce unsupported information.

A future LLM-based implementation could produce more fluent synthesized answers, but would require additional prompt design, grounding validation, token-cost management, and answer faithfulness evaluation.

The current implementation should therefore be understood as an extractive RAG baseline rather than a fully generative RAG system.

## 10. Guardrails and Validation

The application implements:

- Empty question rejection
- Question length validation
- Basic known prompt-injection phrase detection
- File extension validation
- File size validation
- SHA-256 duplicate detection
- Similarity-based abstention
- Source citations from retrieved evidence
- Generic error messages for unexpected processing failures

The prompt-injection filter uses known phrase patterns. It is not a complete defense against indirect prompt injection, adversarial documents, or novel jailbreak techniques.

Authentication and user-level document isolation are not production-ready.

## 11. API Error Handling

The API uses structured HTTP responses.

| Status | Intended use |
|---|---|
| 200 | Successful retrieval or question response |
| 201 | Document uploaded |
| 204 | Document deleted |
| 400 | Invalid question or empty file |
| 404 | Document not found |
| 409 | Duplicate document |
| 415 | Unsupported file format |
| 422 | Request schema validation failure |
| 413 | Upload exceeds configured size |
| 500 | Unexpected processing failure |

Rate limiting and explicit service-unavailable responses require additional implementation before production deployment.

## 12. Logging and Observability

The backend includes request tracking middleware.

It records:

- Unique request ID
- HTTP method
- Request path
- Response status code
- Request processing latency

The request ID is also returned through the `X-Request-ID` response header.

Document and question processing operations log successful actions and unexpected errors.

Sensitive document contents, API keys, and user secrets should not be written to logs.

Centralized monitoring, metrics dashboards, and distributed tracing are future improvements.

## 13. Evaluation Framework

The evaluation framework uses a manually curated golden dataset of 25 questions.

Dataset composition:

- 20 answerable questions
- 5 unanswerable questions

Retrieval metrics:

- Hit Rate@K
- Recall@K
- Mean Reciprocal Rank

The manually verified retrieval relevance subset currently contains five questions.

Threshold experiments evaluate the balance between false abstentions and accepting unanswerable questions.

The framework also compares two chunking configurations.

Faithfulness and correctness require further independent evaluation. Current automated answer checks should not be interpreted as a complete semantic quality judge.

See EVAL.md for results, experimental details, and limitations.

## 14. Reliability and Performance Trade-offs

The implementation uses asynchronous file reading in the upload endpoint and synchronous document processing and vector operations.

This keeps the code straightforward but does not provide complete non-blocking processing for expensive embedding and document extraction operations.

The current service has request ID and latency logging, generic error responses, and basic exception handling.

Additional production hardening should include:

- Explicit request and processing timeouts
- Retry policies for transient external service failures
- Rate limiting
- Service health and dependency checks
- Background processing for large ingestion jobs
- Centralized monitoring and alerting
- Secure authentication and access control

Retries should only be introduced for operations that are safe to repeat and for failures known to be transient.

## 15. Current Limitations

- Extractive answers rather than LLM-generated synthesis
- Basic phrase-based prompt-injection detection
- Demo authentication rather than production JWT
- No per-user document isolation
- Limited manually verified retrieval dataset
- No comprehensive semantic faithfulness evaluation
- No complete rate-limiting or retry implementation
- Local ChromaDB deployment rather than managed production infrastructure

## 16. Future Improvements

- Grounded LLM-based answer generation
- Secure JWT authentication
- Per-user document isolation
- Stronger prompt-injection defenses
- Expanded golden evaluation dataset
- Semantic answer-quality evaluation
- Rate limiting and resilient timeout/retry handling
- Centralized monitoring and production deployment

# RAG Evaluation

## 1. Evaluation Dataset

The evaluation dataset contains 25 questions:

- 20 answerable questions
- 5 unanswerable questions

The dataset is stored in `app/evaluation/golden_dataset.json`.

Five answerable questions (Q1–Q5) have manually verified relevant chunk IDs. These questions are used for retrieval ranking evaluation.

## 2. Evaluation Method

The system retrieves the top 5 chunks for each question using ChromaDB and Sentence Transformers.

A similarity threshold determines whether the system abstains:

- Similarity below threshold: abstain
- Similarity at or above threshold: accept retrieved context

The current configured similarity threshold is 0.30.

Evaluation includes:

- Threshold-based abstention experiments.
- Chunking configuration comparison.
- Hit Rate@5.
- Recall@5.
- Mean Reciprocal Rank (MRR).
- Average retrieval latency.

## 3. Threshold Experiments

Two experiments were performed using the same dataset and `top_k = 5`.

| Metric | Threshold 0.30 | Threshold 0.20 |
|---|---:|---:|
| Total questions | 25 | 25 |
| Answerable questions | 20 | 20 |
| Unanswerable questions | 5 | 5 |
| Total abstentions | 6 | 2 |
| Answerable questions rejected | 1 | 0 |
| Unanswerable questions rejected | 5 | 2 |
| Unanswerable questions incorrectly accepted | 0 | 3 |

Results are stored in:

- `app/evaluation/evaluation_results_030.json`
- `app/evaluation/evaluation_results_020.json`

### Threshold Analysis

At threshold 0.30, the system abstained on all five designated unanswerable questions but also rejected one answerable question.

At threshold 0.20, the system accepted all answerable questions but also accepted three designated unanswerable questions.

This demonstrates the trade-off between answer coverage and safe abstention.

## 4. Retrieval Ranking Metrics

Retrieval ranking metrics were calculated using the five manually verified questions (Q1–Q5) with the existing 800/150 chunk configuration.

| Metric | Result |
|---|---:|
| Verified questions | 5 |
| Hit Rate@5 | 1.000 (100%) |
| Recall@5 | 1.000 (100%) |
| Mean Reciprocal Rank (MRR) | 0.667 (66.7%) |

### Metric Interpretation

- **Hit Rate@5:** All five evaluated questions retrieved at least one relevant chunk in the top five results.
- **Recall@5:** All manually identified relevant chunks for these five questions were retrieved in the top five.
- **MRR:** The average reciprocal rank of the first relevant result was approximately 0.667.

These results apply only to the five-question manually verified subset. They should not be interpreted as performance across the complete dataset.

## 5. Chunking Configuration Comparison

Two chunking configurations were evaluated using the same source PDF (`main_notes.pdf`) and the same 25 golden questions.

Both configurations used:

- Sentence Transformers embeddings.
- ChromaDB cosine-distance retrieval.
- Top 5 retrieved results.
- Similarity threshold of 0.30.

| Setting / Metric | Config A | Config B |
|---|---:|---:|
| Chunk size | 800 | 500 |
| Chunk overlap | 150 | 100 |
| Total chunks | 863 | 1,313 |
| Hit Rate@5 | 100% | 100% |
| Recall@5 | 100% | 90% |
| MRR | 0.6667 | 0.7067 |
| Average retrieval latency | 0.0208 sec | 0.1265 sec |

### Configuration Analysis

**Config A: 800 characters, 150 overlap**

- Produced 863 chunks.
- Achieved 100% Hit Rate@5 and 100% Recall@5 on the verified subset.
- Recorded an average retrieval latency of 0.0208 seconds in this run.
- Uses fewer chunks than Config B.

**Config B: 500 characters, 100 overlap**

- Produced 1,313 chunks.
- Achieved 100% Hit Rate@5.
- Recall@5 was 90% on the verified subset.
- MRR was approximately 0.707.
- Recorded an average retrieval latency of 0.1265 seconds in this run.

### Relevance Mapping and Limitations

The original manually verified relevant chunk IDs belong to the existing 800/150 configuration.

For the comparison, these original chunk IDs were mapped to their source page numbers. Retrieved chunks from both configurations were then evaluated using page-level relevance.

Therefore, the comparison uses a page-level relevance proxy rather than independently verified exact chunk IDs for each configuration.

Only five questions have manually verified relevance labels. The comparison is useful as an initial experiment but is not a complete retrieval benchmark.

Latency values are from a single experiment run and may vary with hardware, model warm-up, and system load. Repeated runs are needed for a more reliable latency comparison.

### Configuration Decision

Config A (800/150) is retained as the current default configuration.

It achieved 100% Recall@5 on the verified subset and had lower measured latency in this experiment. Config B achieved a slightly higher MRR, but lower Recall@5.

This is a provisional engineering choice based on the current limited evaluation, not proof that Config A is universally better.

Results are stored in:

`app/evaluation/chunking_comparison_results.json`

The comparison is implemented in:

`app/evaluation/run_evaluation.py`

## 6. Evaluation Scripts and Results

The evaluation scripts and generated results are stored in `app/evaluation/`.

Important files:

- `golden_dataset.json` — evaluation questions and manually verified relevance labels.
- `run_evaluation.py` — chunking configuration comparison.
- `evaluation_results.json` — baseline retrieval evaluation.
- `evaluation_results_020.json` — threshold 0.20 results.
- `evaluation_results_030.json` — threshold 0.30 results.
- `chunking_comparison_results.json` — chunking comparison results.

## 7. Limitations

- Threshold experiments measure retrieval and threshold-based abstention, not generated-answer correctness.
- The unanswerable labels are based on the intended dataset and should be checked against the uploaded corpus.
- Retrieval ranking metrics are currently calculated for only five manually verified questions.
- The remaining answerable questions need manually verified relevant chunk IDs before full-dataset ranking metrics can be reported.
- The chunking comparison uses source-page relevance as a proxy, not exact chunk-level relevance for both configurations.
- Latency measurements are from a single run and require repeated trials.
- Faithfulness and answer correctness require separate evaluation.
- Similarity scores alone do not establish whether an answer is correct.
- A high retrieval score on a small verified subset does not guarantee general retrieval quality.

## 8. Conclusion

The threshold experiments demonstrate a trade-off between answer coverage and safe abstention. Threshold 0.30 was more conservative than threshold 0.20 on the current dataset.

The chunking experiment compared two configurations using the same document and golden questions. Config A (800/150) achieved 100% Hit Rate@5 and Recall@5 on the verified subset, while Config B (500/100) achieved 100% Hit Rate@5 and 90% Recall@5.

Config A is retained as the current default based on its measured recall and latency in this experiment.

However, the evaluation remains limited by the five-question manually verified subset and page-level relevance mapping. Additional relevance annotations, repeated latency experiments, and answer-quality evaluation are needed before making broader performance claims.

def generate_extractive_answer(retrieved_chunks):
    """
    Generate an answer using only the text of retrieved document chunks.

    This implementation follows an extractive RAG approach:
    it combines relevant source passages instead of generating
    new information using a language model.

    Args:
        retrieved_chunks: List of chunks returned by retrieval.

    Returns:
        Combined source text, or an empty string if no usable
        chunks are available.
    """

    # Return an empty answer when retrieval produces no results.
    if not retrieved_chunks:
        return ""

    # Combine non-empty retrieved passages into a single answer.
    return "\n\n".join(
        chunk["text"].strip()
        for chunk in retrieved_chunks
        if chunk.get("text", "").strip()
    )


# ---------------------------------------------------------
# CITATION GENERATION
# ---------------------------------------------------------

def generate_citations(retrieved_chunks):
    """
    Create source citations from retrieved chunk metadata.

    Each citation identifies the source filename, page number,
    chunk position, and similarity score.

    Args:
        retrieved_chunks: List of retrieved document chunks.

    Returns:
        A list of citation dictionaries.
    """

    # Initialize an empty list to store generated citations.
    citations = []

    # Process each retrieved chunk to extract its source information.
    for chunk in retrieved_chunks:
        metadata = chunk["metadata"]

        # Build a citation using the original document metadata.
        citations.append({
            "filename": metadata["filename"],
            "page": metadata["page"],
            "position": metadata["position"],
            "similarity": round(chunk["similarity"], 4),
        })

    # Return all citations associated with the retrieved chunks.
    return citations

# Regular expressions are used to detect known prompt-injection phrases.
import re

# Import upload validation settings from the central configuration.
from app.config import SUPPORTED_EXTENSIONS, MAX_FILE_SIZE


# ---------------------------------------------------------
# PROMPT INJECTION DETECTION PATTERNS
# ---------------------------------------------------------

# Common instruction-manipulation phrases that should be blocked.
# These patterns provide basic input protection, not complete
# protection against every possible prompt-injection technique.
BLOCKED_PATTERNS = [
    r"ignore\s+(all\s+)?previous\s+instructions",
    r"disregard\s+(all\s+)?(previous\s+)?instructions",
    r"forget\s+(all\s+)?(previous\s+)?instructions",
    r"reveal\s+(your\s+)?system\s+prompt",
    r"show\s+(me\s+)?(your\s+)?system\s+prompt",
    r"reveal\s+hidden\s+instructions",
    r"ignore\s+your\s+rules",
    r"bypass\s+(your\s+)?(safety\s+)?(rules|instructions|guardrails)",
    r"act\s+as\s+if\s+you\s+have\s+no\s+restrictions",
    r"developer\s+message",
]


# ---------------------------------------------------------
# QUESTION VALIDATION
# ---------------------------------------------------------

def validate_question(question: str) -> bool:
    """
    Check whether a question contains known prompt-injection phrases.

    Args:
        question: User-provided question.

    Returns:
        True if no blocked pattern is detected; otherwise False.
    """

    # Convert the question to lowercase for case-insensitive matching.
    normalized_question = question.lower()

    # Reject the question if any blocked pattern is found.
    return not any(
        re.search(pattern, normalized_question)
        for pattern in BLOCKED_PATTERNS
    )


# ---------------------------------------------------------
# DOCUMENT UPLOAD VALIDATION
# ---------------------------------------------------------

def validate_upload(filename: str, file_size: int) -> bool:
    """
    Validate uploaded document extension and file size.

    Args:
        filename: Original name of the uploaded file.
        file_size: Size of the uploaded file in bytes.

    Returns:
        True if the file format and size are allowed;
        otherwise False.
    """

    # Extract the file extension and normalize it to lowercase.
    extension = "." + filename.lower().rsplit(".", 1)[-1]

    # Reject filenames without a file extension.
    if "." not in filename:
        return False

    # Reject formats that are not supported by the application.
    if extension not in SUPPORTED_EXTENSIONS:
        return False

    # Accept only non-empty files within the configured size limit.
    return 0 < file_size <= MAX_FILE_SIZE

@app.middleware("http")
async def request_logging_middleware(request: Request, call_next):
    request_id = str(uuid.uuid4())
    start_time = time.perf_counter()

    try:
        # Identify the client using its direct connection IP.
        client_ip = (
            request.client.host
            if request.client
            else "unknown"
        )

        current_time = time.monotonic()

        # Apply rate limiting to API routes.
        if request.url.path.startswith("/api/"):

            window_start, request_count = _rate_limit_store.get(
                client_ip,
                (current_time, 0),
            )

            # Start a fresh window when the previous one expires.
            if current_time - window_start >= RATE_LIMIT_WINDOW_SECONDS:
                window_start = current_time
                request_count = 0

            # Reject requests after the configured limit.
            if request_count >= RATE_LIMIT_REQUESTS:

                retry_after = max(
                    1,
                    int(
                        RATE_LIMIT_WINDOW_SECONDS
                        - (current_time - window_start)
                    ),
                )

                duration_ms = round(
                    (time.perf_counter() - start_time) * 1000,
                    2,
                )

                logger.warning(
                    "request_id=%s method=%s path=%s "
                    "status_code=429 client_ip=%s latency_ms=%s",
                    request_id,
                    request.method,
                    request.url.path,
                    client_ip,
                    duration_ms,
                )

                return JSONResponse(
                    status_code=429,
                    content={
                        "detail": "Too many requests. Please try again later.",
                        "request_id": request_id,
                    },
                    headers={
                        "X-Request-ID": request_id,
                        "X-RateLimit-Limit": str(RATE_LIMIT_REQUESTS),
                        "X-RateLimit-Remaining": "0",
                        "Retry-After": str(retry_after),
                    },
                )

            # Count the accepted request.
            request_count += 1

            _rate_limit_store[client_ip] = (
                window_start,
                request_count,
            )

            # Periodically remove expired client entries.
            if len(_rate_limit_store) > 10000:
                expired_clients = [
                    ip
                    for ip, (start, _) in _rate_limit_store.items()
                    if current_time - start >= RATE_LIMIT_WINDOW_SECONDS
                ]

                for ip in expired_clients:
                    _rate_limit_store.pop(ip, None)

        # Continue normal request processing.
        response = await call_next(request)

        duration_ms = round(
            (time.perf_counter() - start_time) * 1000,
            2,
        )

        response.headers["X-Request-ID"] = request_id

        if request.url.path.startswith("/api/"):
            response.headers["X-RateLimit-Limit"] = str(
                RATE_LIMIT_REQUESTS
            )

            remaining = max(
                0,
                RATE_LIMIT_REQUESTS
                - _rate_limit_store.get(client_ip, (0, 0))[1],
            )

            response.headers["X-RateLimit-Remaining"] = str(remaining)

        logger.info(
            "request_id=%s method=%s path=%s status_code=%s latency_ms=%s",
            request_id,
            request.method,
            request.url.path,
            response.status_code,
            duration_ms,
        )

        return response

    except Exception:
        duration_ms = round(
            (time.perf_counter() - start_time) * 1000,
            2,
        )

        logger.exception(
            "request_id=%s method=%s path=%s status_code=500 latency_ms=%s",
            request_id,
            request.method,
            request.url.path,
            duration_ms,
        )

        raise

def read_registry() -> list[dict[str, Any]]:
    """
    Read registered document records from the JSON file.
    """

    if not REGISTRY_FILE.exists():
        return []

    try:
        return json.loads(
            REGISTRY_FILE.read_text(encoding="utf-8")
        )

    except (json.JSONDecodeError, OSError):
        logger.exception("Failed to read document registry.")

        raise HTTPException(
            status_code=500,
            detail="Document registry could not be read.",
        )


def save_registry(documents: list[dict[str, Any]]) -> None:
    """
    Save document records to the JSON registry.
    """

    REGISTRY_FILE.write_text(
        json.dumps(documents, indent=2),
        encoding="utf-8",
    )

@router.post(
    "/upload",
    status_code=201,
    response_model=DocumentUploadResponse,
)
async def upload_document(
    file: UploadFile = File(...),
    current_user: dict[str, Any] = Depends(get_current_user),
):
    """
    Upload and index a document for the authenticated user.
    """

    user_id = str(current_user["user_id"])

    filename = Path(file.filename or "").name
    extension = Path(filename).suffix.lower()

    if not filename or not validate_upload(filename, 1):
        raise HTTPException(
            status_code=415,
            detail="Unsupported file format.",
        )

    content = await file.read()

    if not content:
        raise HTTPException(
            status_code=400,
            detail="Uploaded file is empty.",
        )

    if not validate_upload(filename, len(content)):
        raise HTTPException(
            status_code=413,
            detail="File exceeds the 15 MB limit.",
        )

    file_hash = hashlib.sha256(content).hexdigest()

    documents = read_registry()

    # Duplicate detection is restricted to this user.
    for document in documents:
        if (
            document.get("owner_user_id") == user_id
            and document["file_hash"] == file_hash
        ):
            raise HTTPException(
                status_code=409,
                detail="This document has already been uploaded.",
            )

    document_id = str(uuid.uuid4())

    saved_path = UPLOAD_DIR / f"{document_id}{extension}"

    try:
        saved_path.write_bytes(content)

        pages = load_document(str(saved_path))

        chunks = chunk_documents(pages)

        if not chunks:
            raise ValueError(
                "No extractable text found in document."
            )

        # Store vectors with the authenticated user's ID.
        chunk_count = add_chunks(
            document_id=document_id,
            filename=filename,
            chunks=chunks,
            user_id=user_id,
        )

        document_record = {
            "document_id": document_id,
            "filename": filename,
            "file_hash": file_hash,
            "file_size": len(content),
            "chunk_count": chunk_count,
            "file_type": extension,
            "owner_user_id": user_id,
        }

        documents.append(document_record)

        save_registry(documents)

        logger.info(
            "Document uploaded: document_id=%s user_id=%s chunks=%s",
            document_id,
            user_id,
            chunk_count,
        )

        # Do not expose internal ownership metadata in the response.
        response_record = {
            key: value
            for key, value in document_record.items()
            if key != "owner_user_id"
        }

        return {
            "message": "Document uploaded successfully.",
            **response_record,
        }

    except HTTPException:
        saved_path.unlink(missing_ok=True)
        raise

    except ServiceUnavailableError:
        logger.exception(
            "Vector database unavailable during upload: document_id=%s",
            document_id,
        )

        try:
            delete_document(
                document_id,
                user_id=user_id,
            )

        except ServiceUnavailableError:
            logger.exception(
                "Vector rollback failed: document_id=%s",
                document_id,
            )

        saved_path.unlink(missing_ok=True)

        raise HTTPException(
            status_code=503,
            detail=(
                "Document service is temporarily unavailable. "
                "Please try again."
            ),
        )

    except Exception:
        logger.exception(
            "Document processing failed: document_id=%s filename=%s",
            document_id,
            filename,
        )

        try:
            delete_document(
                document_id,
                user_id=user_id,
            )

        except ServiceUnavailableError:
            logger.exception(
                "Vector rollback failed: document_id=%s",
                document_id,
            )

        saved_path.unlink(missing_ok=True)

        raise HTTPException(
            status_code=500,
            detail="Document processing failed. Please try again.",
        )

    """

    question = request.question.strip()
    user_id = str(current_user["user_id"])

        raise HTTPException(
            status_code=400,

        )

            user_id,

        )

            question,
            top_k=request.top_k,

from typing import Any

from fastapi import Depends, HTTPException, status
from fastapi.security import HTTPAuthorizationCredentials, HTTPBearer

from app.auth.database import get_user_by_id
from app.auth.security import decode_access_token


bearer_scheme = HTTPBearer(auto_error=False)


def get_current_user(
    credentials: HTTPAuthorizationCredentials | None = Depends(bearer_scheme),
) -> dict[str, Any]:
    """
    Validate the JWT bearer token and return its registered user.
    """

    unauthorized = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="Invalid or missing authentication token.",
        headers={"WWW-Authenticate": "Bearer"},
    )

    if credentials is None:
        raise unauthorized

    try:
        payload = decode_access_token(credentials.credentials)
        subject = payload.get("sub")

        if not subject:
            raise unauthorized

        user_id = int(subject)

        if user_id <= 0:
            raise unauthorized

        user = get_user_by_id(user_id)

        if user is None:
            raise unauthorized

        return user

    except (jwt.InvalidTokenError, ValueError, TypeError):
        raise unauthorized

def evaluate_answer(answer, retrieved_chunks, citations, abstained):
    """
    Basic source-grounding checks for extractive RAG answers.
    This is a structural evaluation, not a semantic faithfulness score.
    """

    if abstained:
        checks = {
            "abstention_message_present": (
                "could not find relevant information" in answer.lower()
            ),
            "citations_empty": len(citations) == 0,
        }

        return {
            "passed": all(checks.values()),
            "checks": checks,
            "evaluation_type": "abstention_handling",
        }

    source_texts = [
        chunk.get("text", "").strip()
        for chunk in retrieved_chunks
    ]

    checks = {
        "answer_not_empty": bool(answer.strip()),
        "citations_present": len(citations) > 0,
        "retrieved_sources_present": len(source_texts) > 0,
        "answer_matches_retrieved_source": (
            answer.strip() == "\n\n".join(source_texts)
        ),
    }

    return {
        "passed": all(checks.values()),
        "checks": checks,
        "evaluation_type": "structural_source_grounding",
    }

def hit_rate_at_k(retrieved_ids, relevant_ids, k=5):
    """
    Check whether at least one relevant item appears in the top-k results.

    Returns:
        1.0 if a relevant item is found, otherwise 0.0.
    """
    # If there are no relevant items, return 0.0.
    if not relevant_ids:
        return 0.0

    # Consider only the first k retrieved items.
    retrieved_top_k = retrieved_ids[:k]

    # Check whether retrieved and relevant IDs have any overlap.
    return float(bool(set(retrieved_top_k) & set(relevant_ids)))


def recall_at_k(retrieved_ids, relevant_ids, k=5):
    """
    Calculate the fraction of all relevant items found in the top-k results.

    Returns:
        A value between 0.0 and 1.0.
    """
    # If there are no relevant items, return 0.0.
    if not relevant_ids:
        return 0.0

    # Convert the top-k retrieved IDs into a set for comparison.
    retrieved_top_k = set(retrieved_ids[:k])

    # Convert relevant IDs into a set to avoid duplicate counting.
    relevant = set(relevant_ids)

    # Divide the number of relevant items retrieved by total relevant items.
    return len(retrieved_top_k & relevant) / len(relevant)


def reciprocal_rank(retrieved_ids, relevant_ids):
    """
    Calculate the reciprocal rank of the first relevant retrieved item.

    Returns:
        1 / rank of the first relevant item, or 0.0 if none is found.
    """
    # Convert relevant IDs into a set for efficient membership checks.
    relevant = set(relevant_ids)

    # Return 0.0 if no relevant items are available.
    if not relevant:
        return 0.0

    # Enumerate retrieved items starting from rank 1.
    for rank, item_id in enumerate(retrieved_ids, start=1):

        # Check whether the current retrieved item is relevant.
        if item_id in relevant:

            # Return the reciprocal of the first relevant item's rank.
            return 1.0 / rank

    # Return 0.0 if no relevant item was retrieved.
    return 0.0


def mean_reciprocal_rank(results):
    """
    Calculate Mean Reciprocal Rank (MRR) across multiple queries.

    Args:
        results: List of (retrieved_ids, relevant_ids) pairs.

    Returns:
        Average reciprocal rank across all queries.
    """
    # Return 0.0 when there are no query results to evaluate.
    if not results:
        return 0.0

    # Calculate the reciprocal rank separately for each query.
    scores = [
        reciprocal_rank(retrieved, relevant)
        for retrieved, relevant in results
    ]

    # Return the average reciprocal rank across all queries.
    return sum(scores) / len(scores)

def get_relevant_pages(dataset):
    """Map existing verified chunk IDs to their original source pages."""

    # Collect all manually verified chunk IDs from the golden dataset.
    all_ids = sorted({
        chunk_id
        for item in dataset
        for chunk_id in item.get("relevant_chunk_ids", [])
    })

    if not all_ids:
        raise ValueError("No manually verified chunk IDs found.")

    # Retrieve metadata for the verified chunks from the existing collection.
    stored = collection.get(
        ids=all_ids,
        include=["metadatas"],
    )

    # Create a mapping between chunk IDs and their metadata.
    metadata_by_id = dict(zip(stored["ids"], stored["metadatas"]))

    # Stop evaluation if any verified chunk IDs are missing.
    missing = set(all_ids) - set(metadata_by_id)
    if missing:
        raise ValueError(
            f"{len(missing)} verified chunk IDs are missing "
            "from the existing ChromaDB. Check the database."
        )

    # Map each golden question to the pages containing its relevant chunks.
    relevant_pages = {}

    for item in dataset:
        pages = {
            metadata_by_id[chunk_id]["page"]
            for chunk_id in item.get("relevant_chunk_ids", [])
        }
        relevant_pages[item["id"]] = pages

    return relevant_pages


def prepare_collection(config, pages):
    """Create an isolated temporary collection for one configuration."""

    # Generate a unique collection name for this experiment configuration.
    name = f"eval_{config['name'].lower()}"

    # Delete an older temporary collection with the same name, if present.
    try:
        client.delete_collection(name)
    except Exception:
        pass

    # Create a fresh ChromaDB collection using cosine distance.
    eval_collection = client.create_collection(
        name=name,
        metadata={"hnsw:space": "cosine"},
        embedding_function=embedding_function,
    )

    # Split the source pages into chunks using the current configuration.
    chunks = chunk_documents(
        pages,
        chunk_size=config["chunk_size"],
        chunk_overlap=config["chunk_overlap"],
    )

    # Prepare chunk IDs, text, and metadata for ChromaDB.
    ids = []
    documents = []
    metadatas = []

    for index, chunk in enumerate(chunks):
        ids.append(f"{name}_{index}")
        documents.append(chunk["text"])
        metadatas.append({
            "page": chunk["page"],
            "position": chunk["position"],
        })

    # Add all generated chunks to the temporary collection.
    if ids:
        eval_collection.add(
            ids=ids,
            documents=documents,
            metadatas=metadatas,
        )

    return eval_collection, len(chunks)


def evaluate_configuration(config, dataset, pages, relevant_pages):
    """Evaluate retrieval quality and latency for one chunking configuration."""

    # Build a temporary vector collection for this configuration.
    eval_collection, chunk_count = prepare_collection(config, pages)

    # Initialize metric and abstention counters.
    metric_rows = []
    abstained_count = 0
    answerable_abstained = 0
    unanswerable_not_abstained = 0
    total_latency = 0.0
    question_results = []

    # Evaluate every question in the golden dataset.
    for item in dataset:
        start_time = time.perf_counter()

        # Retrieve the top-k most relevant chunks for the question.
        results = eval_collection.query(
            query_texts=[item["question"]],
            n_results=min(TOP_K, chunk_count),
            include=["documents", "metadatas", "distances"],
        )

        # Measure retrieval time for this question.
        latency = time.perf_counter() - start_time
        total_latency += latency

        # Extract retrieved chunk metadata and cosine distances.
        metadatas = results["metadatas"][0]
        distances = results["distances"][0]

        # Convert cosine distances into bounded similarity scores.
        matches = [
            {
                "page": metadata["page"],
                "similarity": max(0.0, min(1.0, 1.0 - distance)),
            }
            for metadata, distance in zip(metadatas, distances)
        ]

        # Abstain if no chunks were retrieved or all scores are below threshold.
        abstained = (
            not matches
            or max(match["similarity"] for match in matches)
            < SIMILARITY_THRESHOLD
        )

        if abstained:
            abstained_count += 1

        # Track answerable questions that were incorrectly rejected.
        if item["answerable"] and abstained:
            answerable_abstained += 1

        # Track unanswerable questions that were not rejected.
        if not item["answerable"] and not abstained:
            unanswerable_not_abstained += 1

        # Calculate retrieval metrics only for questions with verified relevance.
        relevant = relevant_pages.get(item["id"], set())

        if relevant:
            retrieved_pages = [match["page"] for match in matches]

            hit = hit_rate_at_k(
                retrieved_pages, list(relevant), TOP_K
            )
            recall = recall_at_k(
                retrieved_pages, list(relevant), TOP_K
            )
            rr = reciprocal_rank(
                retrieved_pages, list(relevant)
            )

            metric_rows.append({
                "hit_rate_at_5": hit,
                "recall_at_5": recall,
                "reciprocal_rank": rr,
            })

        # Save the retrieval outcome and latency for this question.
        question_results.append({
            "question_id": item["id"],
            "retrieved_pages": [m["page"] for m in matches],
            "abstained": abstained,
            "latency_seconds": round(latency, 4),
        })

    # Calculate average retrieval metrics across verified questions.
    if metric_rows:
        verified_pairs = [
            (
                [
                    page
                    for page in row["retrieved_pages"]
                ],
                list(relevant_pages[row["question_id"]]),
            )
            for row in question_results
            if row["question_id"] in relevant_pages
            and relevant_pages[row["question_id"]]
        ]

        metrics = {
            "verified_question_count": len(metric_rows),
            "hit_rate_at_5": sum(
                row["hit_rate_at_5"] for row in metric_rows
            ) / len(metric_rows),
            "recall_at_5": sum(
                row["recall_at_5"] for row in metric_rows
            ) / len(metric_rows),
            "mrr": mean_reciprocal_rank(verified_pairs),
        }
    else:
        # Return null metrics if no questions have verified relevance.
        metrics = {
            "verified_question_count": 0,
            "hit_rate_at_5": None,
            "recall_at_5": None,
            "mrr": None,
        }

    # Collect all experiment results in one dictionary.
    result = {
        "configuration": config,
        "chunk_count": chunk_count,
        "retrieval_metrics": metrics,
        "total_questions": len(dataset),
        "abstained_count": abstained_count,
        "answerable_questions_abstained": answerable_abstained,
        "unanswerable_questions_not_abstained": (
            unanswerable_not_abstained
        ),
        "average_retrieval_latency_seconds": round(
            total_latency / len(dataset), 4
        ),
        "question_results": question_results,
    }

    # Remove the temporary collection after the experiment finishes.
    try:
        client.delete_collection(eval_collection.name)
    except Exception:
        pass

    return result


def evaluate():

# ---------------------------------------------------------
# DOCUMENT TEXT CHUNKING
# ---------------------------------------------------------

def chunk_documents(
    pages: list[dict],
    chunk_size: int = 800,
    chunk_overlap: int = 150,
) -> list[dict]:
    """
    Split extracted document text into smaller overlapping chunks.

    Chunking makes long documents easier to process, embed,
    store, and search during retrieval.

    Original page numbers and chunk positions are preserved
    to support source citations.

    Args:
        pages: Extracted document pages with text and page numbers.
        chunk_size: Maximum number of characters in each chunk.
        chunk_overlap: Number of overlapping characters between chunks.

    Returns:
        A list of dictionaries containing chunk text,
        original page number, and chunk position.

    Raises:
        ValueError: If chunk size or overlap settings are invalid.
    """

    # Chunk size must be a positive number.
    if chunk_size <= 0:
        raise ValueError("chunk_size must be greater than zero.")

    # Overlap must be non-negative and smaller than chunk size.
    if chunk_overlap < 0 or chunk_overlap >= chunk_size:
        raise ValueError(
            "chunk_overlap must be non-negative and smaller than chunk_size."
        )

    # Store all generated chunks from the supplied document pages.
    chunks = []

    # Calculate the distance between consecutive chunk starting positions.
    # This creates overlapping chunks to preserve context.
    step = chunk_size - chunk_overlap

    # Process each extracted page separately.
    for page_data in pages:
        text = page_data["text"]
        page_number = page_data["page"]

        # Start extracting text from the beginning of the current page.
        start = 0

        # Continue until the complete page text has been processed.
        while start < len(text):
            # Extract a chunk using the configured maximum size.
            chunk_text = text[start:start + chunk_size].strip()

            # Ignore chunks that contain only whitespace.
            if chunk_text:
                chunks.append({
                    "text": chunk_text,

                    # Preserve the original page or slide number.
                    "page": page_number,

                    # Assign a sequential position to each generated chunk.
                    "position": len(chunks),
                })

            # Move forward while retaining the configured overlap.
            start += step

    # Return all generated chunks with their source metadata.
    return chunks

# Path provides cross-platform file path handling.
from pathlib import Path

# Import libraries for extracting text from supported document formats.
from docx import Document
from pptx import Presentation
from pypdf import PdfReader


# File formats supported by the document loading pipeline.
SUPPORTED_EXTENSIONS = {".pdf", ".docx", ".pptx", ".txt", ".md"}


# ---------------------------------------------------------
# DOCUMENT TEXT EXTRACTION
# ---------------------------------------------------------

def load_document(file_path: str) -> list[dict]:
    """
    Extract text and source metadata from a supported document.

    Supported formats:
        PDF: Extract text page by page.
        DOCX: Extract text from paragraphs.
        PPTX: Extract text from individual slides.
        TXT/MD: Read the complete text file.

    Args:
        file_path: Path to the uploaded document.

    Returns:
        A list of dictionaries containing extracted text
        and its corresponding page or slide number.

    Raises:
        ValueError: If the format is unsupported or no extractable
        text is found in the document.
    """

    # Convert the supplied file path into a Path object.
    path = Path(file_path)

    # Normalize the extension to lowercase for reliable validation.
    extension = path.suffix.lower()

    # Reject unsupported document formats.
    if extension not in SUPPORTED_EXTENSIONS:
        raise ValueError(f"Unsupported file format: {extension}")

    # Store extracted text and its original source location.
    pages = []

    # -----------------------------------------------------
    # PDF TEXT EXTRACTION
    # -----------------------------------------------------
    if extension == ".pdf":
        reader = PdfReader(str(path))

        # Extract text separately from each PDF page.
        for page_number, page in enumerate(reader.pages, start=1):
            text = page.extract_text() or ""

            # Ignore pages that contain no extractable text.
            if text.strip():
                pages.append({
                    "text": text,
                    "page": page_number,
                })

    # -----------------------------------------------------
    # DOCX TEXT EXTRACTION
    # -----------------------------------------------------
    elif extension == ".docx":
        document = Document(str(path))

        # Extract non-empty paragraphs and combine them into one text block.
        text = "\n".join(
            paragraph.text
            for paragraph in document.paragraphs
            if paragraph.text.strip()
        )

        # Store extracted DOCX text with a default page reference.
        if text.strip():
            pages.append({"text": text, "page": 1})

    # -----------------------------------------------------
    # PPTX TEXT EXTRACTION
    # -----------------------------------------------------
    elif extension == ".pptx":
        presentation = Presentation(str(path))

        # Process each presentation slide independently.
        for slide_number, slide in enumerate(
            presentation.slides, start=1
        ):
            # Extract text from shapes that contain text frames.
            text = "\n".join(
                shape.text
                for shape in slide.shapes
                if shape.has_text_frame and shape.text.strip()
            )

            # Preserve the original slide number as source metadata.
            if text.strip():
                pages.append({
                    "text": text,
                    "page": slide_number,
                })

    # -----------------------------------------------------
    # TXT AND MARKDOWN TEXT EXTRACTION
    # -----------------------------------------------------
    else:
        # Read plain-text content using UTF-8 encoding.
        text = path.read_text(encoding="utf-8")

        if text.strip():
            pages.append({"text": text, "page": 1})

    # Reject documents that produce no usable text.
    if not pages:
        raise ValueError("The document contains no extractable text.")

    # Return extracted text together with source location metadata.
    return pages

def add_chunks(
    document_id: str,
    filename: str,
    chunks: list[dict[str, Any]],
    user_id: str = "legacy",
) -> int:
    """
    Store document chunks with user ownership metadata.

    Args:
        document_id: Unique document identifier.
        filename: Original document filename.
        chunks: Extracted document chunks.
        user_id: Owner of the uploaded document.

    Returns:
        Number of stored chunks.
    """

    if not chunks:
        raise ValueError("No chunks provided.")

    if not user_id:
        raise ValueError("user_id cannot be empty.")

    ids = []
    documents = []
    metadatas = []

    for index, chunk in enumerate(chunks):
        ids.append(f"{document_id}_{index}")
        documents.append(chunk["text"])

        metadatas.append({
            "document_id": document_id,
            "filename": filename,
            "page": chunk["page"],
            "position": chunk["position"],
            "user_id": str(user_id),
        })

    try:
        collection.add(
            ids=ids,
            documents=documents,
            metadatas=metadatas,
        )

        logger.info(
            "Document chunks stored: document_id=%s user_id=%s count=%s",
            document_id,
            user_id,
            len(ids),
        )

        return len(ids)

    except Exception as exc:
        logger.exception(
            "Failed to add document chunks: document_id=%s",
            document_id,
        )

        raise ServiceUnavailableError(
            "Document storage is temporarily unavailable."
        ) from exc

def search_chunks(
    query: str,
    top_k: int = 5,
    user_id: str = "legacy",
) -> list[dict[str, Any]]:
    """
    Retrieve relevant chunks belonging only to the specified user.

    Args:
        query: User's search question.
        top_k: Maximum number of chunks to retrieve.
        user_id: Owner whose documents may be searched.

    Returns:
        Retrieved chunks with metadata and similarity scores.
    """

    if not isinstance(query, str) or not query.strip():
        raise ValueError("Query cannot be empty.")

    if not isinstance(top_k, int) or isinstance(top_k, bool) or top_k <= 0:
        raise ValueError("top_k must be greater than zero.")

    if not user_id:
        raise ValueError("user_id cannot be empty.")

    try:
        user_filter = {
            "user_id": str(user_id)
        }

        # Count this user's chunks using collection.get().
        # This is compatible with ChromaDB versions where
        # collection.count() does not accept a where argument.
        user_documents = collection.get(
            where=user_filter,
            include=[],
        )

        total_chunks = len(user_documents["ids"])

        if total_chunks == 0:
            logger.info(
                "No document chunks found for user_id=%s",
                user_id,
            )
            return []

        results = collection.query(
            query_texts=[query],
            n_results=min(top_k, total_chunks),
            where=user_filter,
            include=[
                "documents",
                "metadatas",
                "distances",
            ],
        )

        matches = []

        for text, metadata, distance in zip(
            results["documents"][0],
            results["metadatas"][0],
            results["distances"][0],
        ):
            similarity = max(
                0.0,
                min(1.0, 1.0 - distance),
            )

            matches.append({
                "text": text,
                "metadata": metadata,
                "distance": distance,
                "similarity": similarity,
            })

        logger.info(
            "Vector search completed: user_id=%s retrieved_count=%s",
            user_id,
            len(matches),
        )

        return matches

    except Exception as exc:
        logger.exception(
            "Failed to search ChromaDB for user_id=%s",
            user_id,
        )

        raise ServiceUnavailableError(
            "Document retrieval is temporarily unavailable."
        ) from exc

def delete_document(
    document_id: str,
    user_id: str | None = None,
) -> None:
    """
    Delete document vectors, optionally restricted to their owner.

    Args:
        document_id: Unique document identifier.
        user_id: If supplied, restrict deletion to this owner.
    """

    try:
        if user_id is None:
            delete_filter = {
                "document_id": document_id
            }
        else:
            delete_filter = {
                "$and": [
                    {"document_id": document_id},
                    {"user_id": str(user_id)},
                ]
            }

        collection.delete(
            where=delete_filter
        )

        logger.info(
            "Document vectors deleted: document_id=%s user_id=%s",
            document_id,
            user_id if user_id is not None else "all",
        )

    except Exception as exc:
        logger.exception(
            "Failed to delete document vectors: document_id=%s",
            document_id,
        )

        raise ServiceUnavailableError(
            "Document storage is temporarily unavailable."
        ) from exc

from app.evaluation.metrics import (
    hit_rate_at_k,
    recall_at_k,
    reciprocal_rank,
    mean_reciprocal_rank,
)


def test_hit_rate_at_k():
    """Check whether at least one relevant result appears in the top-k results."""

    # A relevant item ("b") is present in the first two results.
    assert hit_rate_at_k(["a", "b", "c"], ["b"], k=2) == 1.0

    # No relevant item is present in the first two results.
    assert hit_rate_at_k(["a", "b", "c"], ["d"], k=2) == 0.0


def test_recall_at_k():
    """Check the proportion of relevant items retrieved within the top-k results."""

    # Two items are relevant ("a" and "c"), but only "a" appears in the top two.
    # Therefore, recall is 1 out of 2 relevant items.
    assert recall_at_k(["a", "b", "c"], ["a", "c"], k=2) == 0.5


def test_reciprocal_rank():
    """Check the reciprocal rank of the first relevant result."""

    # The first relevant result is at position 2, so reciprocal rank is 1/2.
    assert reciprocal_rank(["a", "b", "c"], ["b"]) == 0.5

    # No relevant result is found, so reciprocal rank is zero.
    assert reciprocal_rank(["a", "b"], ["c"]) == 0.0


def test_mean_reciprocal_rank():
    """Check that MRR is calculated as the average reciprocal rank."""

    results = [
        (["a", "b"], ["a"]),  # First result is relevant: reciprocal rank = 1.0.
        (["a", "b"], ["b"]),  # Second result is relevant: reciprocal rank = 0.5.
    ]

    # Mean reciprocal rank = (1.0 + 0.5) / 2 = 0.75.
    assert mean_reciprocal_rank(results) == 0.75


def test_empty_relevant_ids():
    """Verify that metrics return zero when no relevant IDs are provided."""

    # Without relevant document IDs, no result can count as a successful retrieval.
    assert hit_rate_at_k(["a"], []) == 0.0
    assert recall_at_k(["a"], []) == 0.0
    assert reciprocal_rank(["a"], []) == 0.0


def test_empty_results():
    """Verify that MRR returns zero when the evaluation dataset is empty."""

    # There are no query-result pairs to evaluate.
    assert mean_reciprocal_rank([]) == 0.0

from app.ingestion.vector_store import search_chunks


def test_search_empty_query():
    """Verify that an empty search query raises a ValueError."""

    try:
        search_chunks("")
        # Fail the test if the function does not reject an empty query.
        assert False, "Expected ValueError for empty query"
    except ValueError as exc:
        # Confirm that the function returns the expected validation message.
        assert str(exc) == "Query cannot be empty."


def test_search_invalid_top_k():
    """Verify that top_k must be a positive integer."""

    try:
        # A top_k value of zero is invalid because no results were requested.
        search_chunks("machine learning", top_k=0)
        assert False, "Expected ValueError for invalid top_k"
    except ValueError as exc:
        # Check the error message for invalid top_k input.
        assert str(exc) == "top_k must be greater than zero."


def test_search_returns_list():
    """Verify that the vector search function returns a list of results."""

    results = search_chunks("machine learning", top_k=3)

    # The search response should always be a list, even if no matches are found.
    assert isinstance(results, list)


def test_search_result_structure():
    """Verify that each retrieved result contains the required fields."""

    results = search_chunks("machine learning", top_k=3)

    # Check the structure when the vector database returns at least one result.
    if results:
        result = results[0]

        # Each result should include its text, metadata, distance, and similarity.
        assert "text" in result
        assert "metadata" in result
        assert "distance" in result
        assert "similarity" in result

  localStorage.setItem("ragflow_access_token", token);
  localStorage.setItem("ragflow_user", JSON.stringify({ email }));
  localStorage.removeItem("ragflow_demo_user");
}

export function clearSession() {
  localStorage.removeItem("ragflow_access_token");
  localStorage.removeItem("ragflow_user");
  localStorage.removeItem("ragflow_demo_user");
}

export async function apiRequest(path, options = {}) {
  const headers = new Headers(options.headers || {});
  const token = getToken();

  if (token) headers.set("Authorization", `Bearer ${token}`);

  const isFormData = options.body instanceof FormData;
  if (options.body && !isFormData && !headers.has("Content-Type")) {
    headers.set("Content-Type", "application/json");
  }

  let response;
  try {
    response = await fetch(`${API_BASE}${path}`, { ...options, headers });
  } catch {
    throw new Error("Backend se connection nahi ho saka. API server aur VITE_API_URL check karein.");
  }

  const contentType = response.headers.get("content-type") || "";
  const data = contentType.includes("application/json")
    ? await response.json()
    : await response.text();

  if (response.status === 401) {
    clearSession();
    if (window.location.pathname !== "/login") window.location.assign("/login");
    throw new Error("Session expire ya invalid hai. Dobara login karein.");
  }

  if (!response.ok) {
    const detail = typeof data === "object" && data !== null ? data.detail : data;
    throw new Error(detail || `Request failed (${response.status}).`);
  }

  return data;
}

  const [message, setMessage] = useState("");
  const [error, setError] = useState("");
  const fileInput = useRef(null);

  async function loadDocuments() {
    setError("");
    try {
      const data = await apiRequest("/api/documents/");
      setDocuments(Array.isArray(data) ? data : data.documents || []);
    } catch (err) {
      setError(err.message);
    }
  }

  useEffect(() => { loadDocuments(); }, []);

  async function uploadFiles(e) {
    e.preventDefault();
    if (!files.length) { setError("Please select at least one file."); return; }
    setLoading(true);
    setError("");
    setMessage("");
    const uploaded = [];
    const failed = [];

    for (const file of files) {
      const formData = new FormData();
      formData.append("file", file);
      try {
        await apiRequest("/api/documents/upload", { method: "POST", body: formData });
        uploaded.push(file.name);
      } catch (err) {
        failed.push(`${file.name}: ${err.message}`);
      }
    }

    setFiles([]);
    if (fileInput.current) fileInput.current.value = "";
    if (uploaded.length) setMessage(`Uploaded successfully: ${uploaded.join(", ")}`);
    if (failed.length) setError(failed.join(" | "));
    await loadDocuments();
    setLoading(false);
  }

    if (!window.confirm(`Delete ${filename}?`)) return;
    setError("");

      await apiRequest(`/api/documents/${encodeURIComponent(id)}`, { method: "DELETE" });
      setMessage(`${filename} deleted successfully.`);
      await loadDocuments();
    } catch (err) {
      setError(err.message);
    }
  }

  return (
    <div className="page">
      <p className="eyebrow">YOUR PRIVATE KNOWLEDGE BASE</p>

import { useState } from "react";
import { Link, useNavigate } from "react-router-dom";
import { apiRequest, saveSession } from "../lib/api";
import "./Auth.css";

export default function Signup() {
  const [email, setEmail] = useState("");
  const [password, setPassword] = useState("");
  const [error, setError] = useState("");
  const [loading, setLoading] = useState(false);
  const navigate = useNavigate();

  async function handleSignup(e) {
    e.preventDefault();
    setError("");
    setLoading(true);
    try {
      await apiRequest("/api/auth/register", {
        method: "POST",
        body: JSON.stringify({ email: email.trim(), password }),
      });
      const tokenData = await apiRequest("/api/auth/login", {
        method: "POST",
        body: JSON.stringify({ email: email.trim(), password }),
      });
      if (!tokenData.access_token) throw new Error("Account bana, lekin login token nahi mila. Login page se sign in karein.");
      saveSession(tokenData.access_token, email.trim());
      navigate("/dashboard", { replace: true });
    } catch (err) {
      setError(err.message);
    } finally {
      setLoading(false);
    }
  }

  return (
    <div className="auth-page">
      <div className="auth-card">
        <div className="auth-brand">RAG<span>Flow</span></div>
        <div className="auth-icon">âœ¦</div>
        <h1>Create your account</h1>
        <p className="auth-subtitle">Register securely to create your private document workspace.</p>
        <form onSubmit={handleSignup}>
          <label htmlFor="signup-email">Email address</label>
          <input id="signup-email" type="email" autoComplete="email" value={email}
            onChange={(e) => setEmail(e.target.value)} placeholder="you@example.com" required />
          <label htmlFor="signup-password">Password</label>
          <input id="signup-password" type="password" autoComplete="new-password"
            value={password} onChange={(e) => setPassword(e.target.value)}
            placeholder="At least 8 characters" minLength={8} maxLength={128} required />
          {error && <div className="notice error-notice">{error}</div>}
          <button className="auth-button" type="submit" disabled={loading}>
            {loading ? "Creating account..." : "Create account"}
          </button>
        </form>
        <p className="auth-switch">Already have an account? <Link to="/login">Sign in</Link></p>
      </div>
    </div>
  );
}

## 2. Generate embeddings using the configured model



This loads the same Sentence Transformers model configured by the application. It embeds a small sample from each configuration to inspect vector dimensions and generation time.

--- CELL: code ---
import time



model = SentenceTransformer(EMBEDDING_MODEL)

embedding_summary = []



for config_name, chunks in chunk_sets.items():

    sample_texts = [chunk["text"] for chunk in chunks[:10]]



    start_time = time.perf_counter()

    vectors = model.encode(

        sample_texts,

        convert_to_numpy=True,

        show_progress_bar=False,

    )

    elapsed = time.perf_counter() - start_time



    embedding_summary.append({

        "configuration": config_name,

        "embedded_sample_count": len(sample_texts),

        "embedding_dimensions": int(vectors.shape[1]),

        "generation_time_seconds": round(elapsed, 4),

    })



pd.DataFrame(embedding_summary)

## 3. Interpretation and limitations



- Smaller chunks can improve retrieval granularity but increase the number of stored vectors.

- Larger chunks preserve more context but may retrieve less focused passages.

- The embedding sample above is a model sanity check, not a complete retrieval-quality evaluation.

- Retrieval quality must be assessed against manually verified relevant chunk IDs. See Notebook 03.

- Timing is machine-dependent; rerun under the same environment for a fair comparison.

## 1. Retrieve results once for each question



The vector store must already contain the corpus used to create the golden dataset. If ChromaDB is empty or uses a different corpus, stop and ingest the matching documents first.

--- CELL: code ---
retrieval_cache = {}



for item in dataset:

    matches = search_chunks(item["question"], top_k=DEFAULT_TOP_K)



    retrieved_ids = [

        f'{match["metadata"]["document_id"]}_{match["metadata"]["position"]}'

        for match in matches

    ]



    retrieval_cache[item["id"]] = {

        "matches": matches,

        "retrieved_ids": retrieved_ids,

        "max_similarity": max(

            (match["similarity"] for match in matches),

            default=0.0,

        ),

    }



print("Questions retrieved:", len(retrieval_cache))

## 2. Compare abstention thresholds



A question is marked as abstained when there are no matches or the highest similarity is below the selected threshold.

--- CELL: code ---
threshold_rows = []

question_rows = []



for threshold in [0.20, 0.30]:

    abstained_answerable = 0

    accepted_unanswerable = 0

    abstained_total = 0



    for item in dataset:

        cached = retrieval_cache[item["id"]]

        abstained = (

            not cached["matches"]

            or cached["max_similarity"] < threshold

        )



        if abstained:

            abstained_total += 1

            if item["answerable"]:

                abstained_answerable += 1

        elif not item["answerable"]:

            accepted_unanswerable += 1



        question_rows.append({

            "threshold": threshold,

            "question_id": item["id"],

            "answerable": item["answerable"],

            "max_similarity": round(cached["max_similarity"], 4),

            "abstained": abstained,

        })



    threshold_rows.append({

        "threshold": threshold,

        "total_questions": len(dataset),

        "abstained_total": abstained_total,

        "answerable_questions_abstained": abstained_answerable,

        "unanswerable_questions_not_abstained": accepted_unanswerable,

    })



threshold_comparison = pd.DataFrame(threshold_rows)

threshold_comparison

## 3. Ranking metrics on the verified subset



Hit Rate@5, Recall@5 and MRR are computed only for questions with manually verified relevant chunk IDs. Unlabelled questions are not treated as having zero relevant results.

--- CELL: code ---
verified_rows = []



for item in dataset:

    relevant_ids = item.get("relevant_chunk_ids", [])

    if not relevant_ids:

        continue



    retrieved_ids = retrieval_cache[item["id"]]["retrieved_ids"]



    verified_rows.append({

        "question_id": item["id"],

        "hit_rate_at_5": hit_rate_at_k(retrieved_ids, relevant_ids, 5),

        "recall_at_5": recall_at_k(retrieved_ids, relevant_ids, 5),

        "reciprocal_rank": reciprocal_rank(retrieved_ids, relevant_ids),

    })



verified_df = pd.DataFrame(verified_rows)

display(verified_df)



if verified_rows:

    ranking_summary = pd.DataFrame([{

        "verified_question_count": len(verified_rows),

        "hit_rate_at_5": verified_df["hit_rate_at_5"].mean(),

        "recall_at_5": verified_df["recall_at_5"].mean(),

        "mrr": mean_reciprocal_rank([

            (

                retrieval_cache[row["question_id"]]["retrieved_ids"],

                next(

                    item["relevant_chunk_ids"]

                    for item in dataset

                    if item["id"] == row["question_id"]

                ),

            )

            for row in verified_rows

        ]),

    }])

    display(ranking_summary)

else:

    print("No manually verified relevant chunk IDs are available.")

## 4. Evaluation limitations and next steps



1. Only manually labelled questions contribute to ranking metrics. Expand the verified labels before making broad quality claims.

2. Threshold comparison measures abstention trade-offs, not embedding or chunking quality.

3. A proper chunking comparison requires separate vector-store collections populated with each configuration and evaluated against the same gold labels.

4. Retrieval metrics do not prove answer correctness or faithfulness.

5. Preserve the corpus, model name, chunk settings, top-K and threshold when reporting reproducible results.
